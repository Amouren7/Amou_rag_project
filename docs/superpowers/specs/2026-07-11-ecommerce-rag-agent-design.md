# 电商运营知识 RAG Agent 二次开发设计

## 目标

基于 `D:\360ANQUAN\agentic_rag_project-main` 的 MIT 开源 Agentic RAG 基座，在 `D:\CC\rag-project` 完成业务化深度二次开发，形成可运行、可测试、可评测、可演示的电商运营知识 RAG Agent。系统面向运营人员查询商品资料、平台规则、内容规范、运营 SOP 和历史案例，所有回答必须提供可追溯证据。

## 用户流程

1. 运营人员上传或放入 PDF、Markdown、TXT 文档。
2. 摄取程序提取正文和页码/标题等来源信息。
3. 系统优先执行语义切分，失败时回退到递归字符切分，并记录降级原因。
4. 文本块生成 Embedding 后写入 PostgreSQL/pgvector。
5. 用户发起问题，Agent 根据意图调用向量检索、混合检索、全文读取或文档浏览工具。
6. 混合检索将向量召回与中文关键词/模糊匹配结果进行排名融合。
7. Agent 仅基于召回证据生成答案，返回文档名、页码、片段、相关度和检索方式。
8. 无可靠证据时明确拒答或提示补充资料。

## 系统组件

### 文档摄取

- 支持 PDF、Markdown、TXT。
- 保存 `document_id`、文件名、标题、页码、内容类型、块序号、切分方法和自定义元数据。
- PDF 使用现有解析能力；Markdown/TXT 使用轻量文本加载器。
- 语义切分失败、Embedding 失败或数据库写入失败时返回结构化错误，不静默丢失文档。

### 检索层

- 向量召回使用 pgvector 余弦相似度。
- 中文关键词召回采用 PostgreSQL `pg_trgm` 相似度与子串匹配，避免沿用英文 `to_tsvector('english')`。
- 混合检索使用 Reciprocal Rank Fusion 合并两路排名。
- 支持按文档、内容类型和元数据过滤。
- 检索结果统一为包含来源字段的结构化模型。

### Agent 与引用

- 保留并重构四类工具：向量检索、混合检索、全文档读取、文档列表。
- 系统 Prompt 强制优先检索、禁止无来源事实回答、证据不足时拒答。
- 普通响应和 SSE 响应统一返回 `answer`、`citations`、`tools_used`、`session_id`。
- citations 去重后包含文档标题、来源、页码、块 ID、片段、分数和检索方式。

### 模型配置

- LLM 和 Embedding 均采用 OpenAI-compatible 配置。
- 支持独立的 API key、base URL、模型名、超时和向量维度。
- `.env.example` 仅包含空值或安全占位符。
- 单元测试使用 mock，不要求真实模型密钥。

### 会话与 API

- 延续 PostgreSQL 会话和消息持久化。
- 修正上下文读取为最近消息窗口，并保持时间顺序。
- 提供健康检查、文档列表、普通问答、SSE 问答、向量检索和混合检索接口。
- Pydantic 模型校验 TopK、权重、分页和过滤参数边界。

### 评测

- 提供电商示例文档和带标准来源的问答集。
- 离线检索评测计算 Recall@K、MRR 和平均响应时间。
- 引用评测计算应引用问题的 citation coverage。
- 评测结果输出 JSON 和 Markdown；没有真实 API 时仍可使用确定性假数据测试评测逻辑。

## 非目标

- 本阶段不实现企业级 SSO、多租户计费、复杂 RBAC 或 Kubernetes 部署。

- 不宣称多 Agent 系统；本项目定位为单 Agent 多工具的 Agentic RAG。
